$ python3 tools_smoke_check.py --code 363418001 --min-share 0.003 --max-share 0.03

FAIL: share 0.0022 (4/1814) < min 0.003 floor. (RUN 1 measured 6/1809 = 0.0033, just
above the floor.)

Root-cause investigation (this was NOT touched by either adjudicated commit, confirmed):
  $ git diff --stat 78399db0..c7d606d3 -- src/main/resources/modules/pancreatic_cancer.json
  $ git diff --stat c3e19573..HEAD -- src/main/resources/modules/pancreatic_cancer.json
  Both empty -- pancreatic_cancer.json is byte-identical across RUN 1 and RUN 2.

This is a real, deterministic consequence of the current codebase + seed 4444 (Synthea
with a fixed population seed is deterministic; re-running the identical command would
reproduce n_with_dx=4 every time, not a flaky/intermittent result) -- but it is NOT a
pancreatic-module regression. 78399db0 restructured non_small_cell_lung_cancer.json's
Stage_Observation into 4 separate states, changing the number of state-transition
random draws consumed by any person who develops NSCLC. Each person's `personSeed` is
independent, but WITHIN one person's own simulation, changing an earlier-processed
module's state-graph shape shifts that same person's subsequent random draws for
whatever runs later in the same tick -- including, for people who happen to develop
both NSCLC and pancreatic cancer or whose per-tick module iteration order interleaves
with pancreatic_cancer.json's own onset roll, whether that person's independent
pancreatic-onset draw lands positive or negative. This is exactly the fragility the
original task brief flagged for this specific check ("the 1.8 deferred validation,
power-appropriate floor"): at n~1800 with a true rate in the ~0.2-0.3% range, the
0.003 floor requires >=6 events, and Poisson noise around a mean of ~5 events puts a
non-trivial fraction of otherwise-correct runs below that floor on unrelated code
changes elsewhere in the tree -- RUN 1 (6 events) barely cleared it, RUN 2 (4 events)
does not.
=> FAIL. Not one of the 3 adjudicated criteria and not something either adjudicated
commit could have caused, but the controller's criterion 4 asked for re-verification,
and this one does not re-verify. Flagging for controller attention per "do not fail
silently" rather than silently treating it as passed.
