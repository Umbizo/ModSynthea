The controller reviewed the ranked-breakdown finding from section 7 and
ruled the exclude-list approach a dead end: the offenders are a
systemic family of stock SDOH codes that legitimately dominate raw row
counts at full-lifetime export, not a short fixed list that could ever
be fully enumerated. Since the top-share check's actual purpose is
catching a FORK-module disease monoculture (the HOHF I50.83=98%
incident that motivated this whole remediation), the metric was
redefined rather than patched again.

Change 1 — tools_smoke_check.py: added `--top-share-universe FILE`. When
given, the top-share check's *candidate pool* for the "top" seat is
restricted to codes listed in FILE (one code per line; blank lines and
`#`-prefixed comment lines ignored); the *denominator* is unchanged --
still all condition rows (minus any `--exclude-codes`, which remains
supported for back-compat but is no longer used by the gates). This
directly targets "does any ONE fork-disease code dominate the
population's conditions" instead of "does any ONE code of any kind
dominate raw row counts" (which was always going to be won by
frequently-re-asserted stock/SDOH findings at full-lifetime scale).
